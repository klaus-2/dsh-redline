# Contributing

## Setup

```bash
npm run build
npm test
```

No dependencies to install — the plugin is plain Node.js.

`overlay.template.js` + `tencil-overlay.css` are the sources. `lib/overlay.js`
is generated by `npm run build` — never edit it directly. `lib/index.js` (host)
and `lib/client.js` (chat face) are hand-written.

## Smoke suite

`npm test` starts the host on an isolated port (47950, falling back to the next 20) with a
fake target site on a free port, inside a temporary home, and runs the smoke and regression
suites even when one of them fails. The smoke suite covers the proxy, HTML/CSS rewriting,
annotation intake, cropped-screenshot persistence, the context format and overlay integrity.
A green suite is required for every change to `lib/`.

## Code style

- No prose comments in shipped files. Keep the `SPDX-License-Identifier` line, legal
  notices, and one-line contract or safety notes where a reader would otherwise be
  surprised — those notes are deliberate (the bridge contract, the origin-bucket
  rationale, the untrusted-input notes) and they ship. When a decision needs more than
  a line, move it into the README or a doc under `docs/`.
- `npm run strip-comments` reports comment drift in the shipped JS/CSS sources;
  `npm run strip-comments -- --write` applies it (it is a real lexer: strings,
  template literals and regex literals are preserved, and license notices survive
  in the JS/CSS sources). Write mode also removes the contract and safety notes
  described above — it strips every comment that is not a legal notice — so it is a
  deliberate edit, not a formatter.
- User-facing strings go through the locale tables in
  `overlay.template.js` / `lib/client.js`. The JSON files in `locale/` are
  translation mirrors for contributors, not runtime inputs; update the inline
  tables (and the mirrors together). English is the default; regressions in
  the other locales are bugs.
- The English README is the source of truth; the two translations
  (`README.pt-BR.md`, `README.zh-CN.md`) must be updated in the same change.

## Releases

Publishing is CI-only — never run `npm publish` locally (a double publish returns E409).

1. Bump `version` in `package.json` and `PLUGIN_VERSION` in `lib/index.js` so they match.
2. Add a `CHANGELOG.md` section for that version.
3. Run `npm run build` if the overlay sources changed, then `npm test`.
4. Commit, push, tag `vX.Y.Z` and create a GitHub Release titled `dsh-redline vX.Y.Z`.
   The publish workflow runs the suite and publishes to npm.
